# ThinkReader 文章类型与证据归因

文章类型由 App 在写入前检查。测试样例、教学材料及非研究文章自动归为 other，自主按实际内容执行，不要求用户强行选择研究类型。真实研究文章证据不足或混合类型难以判断时，才请用户确认综述还是原创性研究，
不得自行默认。survey 包括叙述性综述、系统综述及 meta-analysis；研究与综述混合的内容逐项归因。

所有批注、问答和输出都区分：本文原创成果、综述作者的分类/综合判断、被引研究的成果、Agent 推断。
未读取被引原论文时只能说“据该综述转述”，不得伪造原论文 EvidenceRef 或声称已经核验原研究。

综述阅读关注范围、研究问题、分类维度、研究路线、代表工作、比较条件、共识、争议和研究空白。
不同数据集、指标、基线和条件的数值不可直接排名。普通综述不因没有原创实验或系统检索流程而被判为缺陷。
系统综述检查原文已报告的检索范围/日期、纳入排除标准和偏倚；meta-analysis 再看效应量、区间、异质性。
原文未报告的信息如实注明，不为模板编造内容。不把综述的检索截止日期当成今天。

批注必须保留必要归因：例如“综述归纳”“某研究报告”，不能压缩成错误的“本文提出/实验表明”。
同一论点优先复用现有 annotation_id；不同条件、反例或冲突观点即使位置相同也分别保留。
同一编号图的子图（包括双栏文章的跨栏图）共用一个来源证据卡片，保留各子图 EvidenceRef，
通过 App 分组解析，不自填坐标。不能只合并 Markdown 链接而留下重复卡片。
核对整页与完整图注，例如 XRO Figure 2 不能漏掉右侧全年 correlation skill；
有独立解释的子图批注和用户修改仍保留，不因位置邻近就合并不同论点。
结构浏览与精读解释可以互补，不因位置重叠直接合并。用户正文、回复、布局和历史来源不得擅自改写。

/review = browse → annotation → summary；/deep-review = browse → deep-annotation → summary。
两者固定阅读全文；focus 只调整强调重点。两种 review 的 summary 使用相同标准、结构、篇幅与证据要求，
不因 deep 模式增加 summary 深度或扩成长报告。summary 直接核对全文，不仅总结已有批注。

综述 summary 的四个标题依次为：综述背景、分类框架、代表研究与结果比较、共识、争议与研究空白。
分类框架需要说明研究的问题、研究路线与分类维度；比较保留成果所属工作与条件。原创研究保持原四标题。

综述 wiki 必须先核对已有论文与 canonical 节点，复用概念、方法与内容来源；遵循 wiki-skill 的综述规则。
综述 codebase 输出代表文章的代码资源目录：工作、方法、GitHub/代码链接、官方或第三方、核验状态与出处；
不生成虚构的统一算法、复现指标或复现规格。未知资源标记未找到，不猜测 URL。
